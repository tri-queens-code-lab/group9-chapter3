# 第一次 Git 实验笔记

## 实验过程

这次实验练习了 Git 的基本工作流程：先用 `git status` 查看仓库状态，再用 `git add` 将指定修改放入暂存区，使用 `git commit` 在本地仓库中保存一次有说明的版本，最后用 `git push` 把本地分支同步到 GitHub。

实验中我从最新的 `main` 分支创建了个人分支 `homework/ttt587`，并且只在 `members/ttt587/README.md` 中记录学习内容。通过这个过程，我进一步理解了工作区、暂存区、本地仓库和远程仓库之间的关系，也认识到多人协作时应当把自己的修改限制在约定范围内。

## 问题回答

### 1. `git add` 的作用

`git add` 用来把工作区中选定的修改加入暂存区，确定这些内容会进入下一次提交。它不会创建提交，也不会把内容上传到远程仓库。例如，`git add notes.md` 会把 `notes.md` 当前的修改加入暂存区。

### 2. `git commit` 的作用

`git commit` 将暂存区中的修改保存为本地仓库里的一次提交，并记录提交作者、时间和说明。每次提交都会形成一个可以追踪的版本节点，方便之后查看历史、比较差异或恢复内容。

### 3. `git restore notes.md` 的作用

在默认情况下，`git restore notes.md` 会撤销 `notes.md` 在工作区中尚未暂存的修改，使它恢复到暂存区所记录的状态。这个操作可能丢失尚未保存的修改，因此执行前要确认这些内容不再需要。

### 4. `commit` 和 `push` 的区别

`commit` 是把暂存区中的修改记录到本地 Git 仓库，提交完成后内容仍只存在本机；`push` 是把本地已有的提交上传到远程仓库。通常先执行 `commit`，再执行 `push`，这样其他协作者才能在远程仓库中看到这些提交。
