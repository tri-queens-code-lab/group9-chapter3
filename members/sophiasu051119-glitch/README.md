Git 本地实验笔记

这次实验主要练习了 Git 的一些基本操作，包括查看文件状态、将修改加入暂存区、提交修改以及撤销未提交的修改。通过实际操作，对 Git 中文件从修改到提交的过程有了更直观的认识。



1. 查看仓库状态

使用git status可以查看当前仓库的状态，例如哪些文件被修改了、哪些文件已经加入暂存区，以及当前所在的分支。在实际操作中，如果不确定文件现在处于什么状态，可以先用这个命令检查。



2. 将修改加入暂存区

使用git add 文件名可以把已经修改的文件加入暂存区。加入暂存区之后，这些修改才会成为下一次 commit 要提交的内容。

例如：git add notes.md 表示把 notes.md 当前的修改加入暂存区。



3. 提交修改

使用git commit -m "提交说明"，可以把暂存区中的内容提交到本地 Git 仓库中。提交时需要写一条说明，用来记录这次修改主要做了什么。

例如：git commit -m "完成第一次 Git 实验笔记"，每一次 commit 都会形成一条提交记录，之后可以通过 Git 的日志查看。



4. 查看提交记录

使用git log --oneline 可以用比较简洁的形式查看之前的提交记录，包括提交编号和对应的提交说明。



5. 撤销工作区中的修改

如果文件已经被修改，但是还没有提交，可以使用git restore 文件名，将文件恢复到修改前的状态。

例如：git restore notes.md 执行后，notes.md 中尚未提交的修改会被撤销，所以在使用这个命令之前需要确认这些修改是否还需要保留。



6. 实验理解

通过这次实验，我理解了 Git 中比较基本的一条操作过程：修改文件 → git add → git commit。其中，修改后的文件先处于工作区，执行 git add 后进入暂存区，再通过 git commit 保存到本地仓库中。Git 可以记录每次提交的变化，这也是后面多人协作和版本管理的基础。



Git 实验总结



1. git add 的作用是：

git add 用来把工作区中已经修改的内容加入暂存区，为下一次提交做准备。它并不是直接把修改保存到 Git 仓库，而是先确定哪些修改需要包含在下一次 commit 中。例如执行 git add notes.md，就是把 notes.md 当前的修改加入暂存区。



2. git commit 的作用是：

git commit 用来把暂存区中的修改正式提交到本地 Git 仓库，并形成一条新的提交记录。每次提交都会保存这一次修改的内容，同时需要填写提交说明，方便之后查看和了解这次提交主要做了什么。



3. git restore notes.md 的作用是：

git restore notes.md 可以撤销 notes.md 在工作区中尚未加入暂存区的修改，使文件恢复到暂存区中记录的状态。执行这个命令后，被撤销的修改一般不能直接通过 Git 找回，所以使用前需要确认这些修改是否还需要保留。



4. commit 与 push 的区别是：

commit 和 push 作用的范围不同。commit 是把修改保存到本地 Git 仓库中，此时提交记录还只存在自己的电脑上；push 是把本地已经产生的提交上传到远程仓库，例如 GitHub。通常需要先完成 commit，再通过 push 把这些提交同步到远程分支。
