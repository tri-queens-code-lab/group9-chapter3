# 第一次 Git 实验笔记

## 实验过程

这次实验主要练习了 Git 的基本操作，包括查看仓库状态、创建个人分支、修改文件、将修改加入暂存区、提交修改、查看提交记录以及将本地提交推送到 GitHub。

通过实际操作，我对 Git 中工作区、暂存区、本地仓库和远程仓库之间的关系有了更加清楚的认识，也了解了在多人协作时使用个人分支的重要性。

### 1. 查看仓库状态

使用：

```bash
git status
```

可以查看当前 Git 仓库的状态，包括当前所在分支、哪些文件被修改、哪些文件已经加入暂存区等。

在进行 Git 操作前，可以先使用 `git status` 确认当前仓库状态，避免误操作。

### 2. 创建个人作业分支

本次实验从 `main` 分支创建个人作业分支：

```bash
git switch -c homework/HNNU-OD
```

创建个人分支以后，可以在自己的分支上完成实验内容，而不会直接修改主分支。

如果分支已经存在，可以使用：

```bash
git switch homework/HNNU-OD
```

切换到该分支。

### 3. 修改个人文件

本次实验中只修改自己的文件：

```text
members/HNNU-OD/README.md
```

在多人协作的仓库中，每个人应尽量只修改自己负责的文件，避免影响其他成员的内容。

### 4. 将修改加入暂存区

文件修改完成以后，使用：

```bash
git add members/HNNU-OD/README.md
```

将修改加入暂存区。

之后可以再次使用：

```bash
git status
```

检查文件是否已经成功进入暂存区。

### 5. 提交修改

使用：

```bash
git commit -m "完成第一次Git实验作业"
```

将暂存区中的修改提交到本地 Git 仓库。

每一次 `commit` 都会形成一条新的提交记录，并保存对应的提交说明。

### 6. 查看提交记录

使用：

```bash
git log --oneline
```

可以用比较简洁的形式查看 Git 提交历史，包括每次提交的编号和提交说明。

### 7. 撤销工作区中的修改

如果对文件进行了修改，但是这些修改不需要保留，可以使用：

```bash
git restore notes.md
```

在默认情况下，该命令会撤销 `notes.md` 在工作区中尚未暂存的修改，使文件恢复为暂存区中记录的状态。

这个操作可能导致尚未保存的修改丢失，因此执行之前需要确认这些内容是否还需要保留。

### 8. 推送到远程仓库

完成本地提交之后，可以使用：

```bash
git push
```

将本地已经产生的提交推送到 GitHub 远程仓库。

第一次推送个人分支时，可以使用：

```bash
git push -u origin homework/HNNU-OD
```

之后就可以在 GitHub 上创建 Pull Request，将个人分支中的修改提交到 `main` 分支进行审核和合并。

## 实验理解

通过这次实验，我理解了 Git 中比较基本的一条工作流程：

```text
修改文件
    ↓
工作区
    ↓
git add
    ↓
暂存区
    ↓
git commit
    ↓
本地仓库
    ↓
git push
    ↓
远程仓库
```

其中，`git add`、`git commit` 和 `git push` 分别负责不同阶段的操作。Git 通过保存每一次提交记录，可以方便地查看项目历史，同时也为多人协作和版本管理提供了基础。

## 第一次 Git 实验总结

### 1. `git add` 的作用是：

`git add` 用于把工作区中已经修改的内容加入暂存区，为下一次提交做准备。

例如：

```bash
git add notes.md
```

表示将 `notes.md` 当前的修改加入暂存区。

`git add` 本身不会产生新的提交，也不会把内容上传到 GitHub，它只是确定哪些修改会进入下一次 `commit`。

### 2. `git commit` 的作用是：

`git commit` 用于将暂存区中的修改保存到本地 Git 仓库，并形成一条新的提交记录。

例如：

```bash
git commit -m "提交第一次Git实验总结"
```

其中 `-m` 后面的内容是本次提交的说明。

每一次 `commit` 都会形成一个可以追踪的版本，之后可以通过 Git 的提交历史查看。

### 3. `git restore notes.md` 的作用是：

在默认情况下：

```bash
git restore notes.md
```

用于撤销 `notes.md` 在工作区中尚未暂存的修改，使工作区中的文件恢复为暂存区中记录的状态。

执行这个命令可能会丢失工作区中尚未保存的修改，因此在使用之前需要确认这些修改是否还需要保留。

### 4. `commit` 与 `push` 的区别是：

`commit` 和 `push` 操作的位置不同。

`commit` 是将暂存区中的修改保存到本地 Git 仓库中。执行 `commit` 后，新的提交记录已经保存在自己的电脑上，但是 GitHub 上的远程仓库不会因此自动更新。

`push` 是将本地已经产生的提交上传到远程仓库，例如 GitHub。

因此通常的操作顺序是：

```text
修改文件 → git add → git commit → git push
```

可以简单理解为：

```text
commit：保存到本地仓库
push：上传到远程仓库
```
